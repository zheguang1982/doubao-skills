# 根据宿主实际能力执行

以当前软件公开给Agent的工具说明、工具返回和当前用户配置为依据。不凭软件名推测功能；“软件能生图”与“本会话能调用生图工具”需要区分。不猜测WorkBuddy、Codex或其他软件的私有工具名、路径和参数。

## 只确认本次所需能力

| 能力 | 需要确认的事实 | 何时需要 |
|---|---|---|
| 生图 | 能否实际生成图片并返回可访问图片/附件 | image及需要插画的PPT |
| 参考图/编辑 | 是否能输入角色/风格图，或局部编辑目标图 | 需要身份一致或修图时 |
| 素材处理 | 是否支持真实透明输出、抠图或图片处理 | 独立透明素材有需要时 |
| 演示文稿 | 能否创建原生文本/形状、放独立图片、导出PPTX | editable-ppt、both |
| 文件与预览 | 是否能保存文件、打包和渲染最终文稿 | 按交付形式需要 |

无需为普通整图任务检查PPT依赖。可在内部记录image_generation、reference_input、image_edit、alpha、native_presentation、file_export、rendering为available/unavailable/unknown，并记依据；不把技术自检表展示在课堂页面中。

## 生图工具选择顺序

1. 当前用户明确指定的、可用且获准使用的工具或模型。
2. 当前宿主内置生图能力，或宿主已连接并可调用的生图工具。直接把提示词交给该工具，不要求用户先配置API。
3. 用户已经配置并允许使用的外部工具/脚本。仅按该环境给出的说明调用；本分享包不提供私人路径，不默认安装或新建API客户端。
4. 无法实际生图：仍完成页面文案、视觉规范和逐页提示词；如有可用且适合的用户素材，可继续排版。明确图片未生成，不能说任务全部完成。仅在完成工作确实需要时，简短指出需要开放哪项能力；不把购买API当成唯一方案。

工具不可用时先检查已经可用的其他路径，而非反复调用同一个失败工具。不要未经用户要求切换到额外收费服务。模型与尺寸选项只使用宿主工具支持的值；未指定模型就让宿主按当前配置生成。

## 输出模式不随能力静默变化

| 本次目标与能力 | 行为 |
|---|---|
| 只要整图，内置生图可用，无代码/PPT | 直接逐页生图与检查；不查Node、Python或PPT库，不要求API |
| 要可编辑PPT，生图与原生PPT导出都可用 | 独立素材＋原生文字/图解，导出并检查PPT |
| 要可编辑PPT，仅生图可用 | 生成独立素材、准确文案和组装计划；说明可编辑PPT尚未导出。整图效果稿不能冒充最终PPT |
| 要可编辑PPT，有原生PPT工具但无生图 | 用用户已有且适用的插画继续；没有时可完成文案/布局草稿，明确缺插画，不用程序画假插画替代所需卡通插画 |
| 要两种，原生PPT和图片导出可用 | 完成可编辑PPT后导出逐页图，保持内容与版本一致 |
| 要两种，只有生图 | 可完成要求的整图；另交独立素材/文案/组装计划时明确PPT部分未完成 |
| 无实际生图与文件生成能力 | 交付可复制文本方案与提示词，注明未生成图片/PPT，不给不存在的下载链接 |

## 分享与安装边界

分享的是文件夹、教学/视觉规则和通用提示词，不是宿主软件的权限、账号、模型或配额。按目标软件已有的Skill/自定义指令导入方式使用；不编造安装入口。若软件只支持文本指令，读取SKILL.md及相关references，并通过该软件支持的方式提供参考图。

文件支持不可用时可把计划、文案、提示词直接写在回复中；不要要求所有软件写入同一磁盘位置。agents/openai.yaml只是Codex UI元数据，其他软件无需实现它。明确说明“已在某平台实测”必须有实际运行证据。
