# 直播/活动邀请函 H5

把一次邀约做成手机上能点着玩的五屏 H5。核心记忆点：拒绝按钮会躲，只有答应才能往下走。

## 首轮引导

**用户首次触发本 skill 且未提供完整信息时，先原样输出下面这段引导语，然后停下等用户回复。不要追问、不要自行编造内容、不要先生成。**

```
好，我来做这个邀请函 H5。最少只需两样：

1. **讲座主题** —— 比如「AI 赋能语文教学」
2. **实践方向** —— 讲座要带大家做的 1~6 个方向/环节，我做成选项卡
   （比如「AI 备课」「课堂互动」「作业批改」）

顺带能补充更好（不填也能生成，用默认值/占位）：
3. **嘉宾姓名** —— 邀请谁（不填默认"嘉宾"，告诉我可替换）
4. **讲座日期** —— 哪天，最好带时间（不填显示"日期待定"，建议补上）
5. **主办方** —— 谁办的（不填默认"豆包"）

直接按顺序发我就行。
```

用户回复后，若某项仍缺失：能合理默认的就默认（见下方默认值），不能默认的（主题、实践）再单独追问那一项。

用户一次性说清了全部信息（例如「邀请王老师参加 10 月 16 日的 AI 赋能语文教学讲座，带大家做 AI 备课和课堂互动」），**跳过引导语直接生成**。

## 生成流程

### 1. 写配置文件

把信息整理成 JSON。完整字段说明见 [references/config-schema.md](references/config-schema.md)，常用字段：

```json
{
  "guest": "王老师",
  "event_name": "AI 赋能语文教学",
  "event_date": "2026-10-16",
  "time": "19:30",
  "brand": "刘飞飞名师工作室",
  "session": "专题讲座",
  "slogan": "让 AI 成为课堂的得力助手",
  "role": "讲师",
  "invite_line": "一场只聊实战的 AI 教学实践分享，主讲位留给你。",
  "signature": "负责给你搭台的我",
  "topics": [
    {"name": "AI 备课", "desc": "十分钟备好一节课"},
    {"name": "课堂互动", "desc": "AI 助手的实时应用"},
    {"name": "作业批改", "desc": "AI 批改效率翻倍"}
  ]
}
```

核心必填：`event_name`（主题）、`topics`（实践方向，1~6 项）。其余留空自动填默认值；`guest` 默认"嘉宾"占位、`event_date` 默认"日期待定"占位，生成后提醒用户可补齐。

**非讲座场景（生日、聚会、约会、婚礼答谢等）**：把 `invite_title` 换成「生日邀请函」之类、`role` 换成「寿星」「主角」等即可；`session` 留空——留空时屏1只显示主办方、屏4标题简化为「想参加什么？」、票根不再出「场次」行。模板文案已中性化（不含「主讲位」这类讲座专用词），不需要为聚会场景改模板。

**`role` 决定全站称谓**（嘉宾 / 讲师 / 主播 / 老师…），会同步影响屏1标签、票根身份。默认「嘉宾」。

**日期只支持单个**——页面上是确定好的一天，对方只能确认不能改期。星期由脚本按真实日历算，不要手写。

### 2. 执行生成

```bash
python scripts/build_invite.py config.json -o 输出目录/index.html
```

脚本会打印嘉宾、活动、日期、实践方向数量、文件大小和外链数量。**外部引用必须是 0**，非 0 会告警——含外链的产物在发布时可能因外链不可达而失败。

脚本对每处替换都做存在性校验，模板改版导致锚点失效时会直接报错退出，不会静默产出错误产物。生成后还会自查模板原始内容（锚点残留）是否仍存在、回读校验写入一致性。

### 3. 交付

用 present_files 交付生成的 HTML。**不要代替用户发布**——发布由用户在产物预览界面自行点击发布按钮完成。

## 内容撰写建议

用户只给了主题/实践这类骨架时，其余文案由你补写，注意：

- **`invite_line`（邀请语）**：说清这场活动值得来的理由，一句话，20~35 字。避免"诚挚邀请您参加"这类套话。
- **`topics` 的 `desc`**：每项 6~12 字，写"讲了能得到什么"而不是重复标题。选项在 3 个左右时观感最好；给到 4 个以上时最后一项适合放"我全都要"这类兜底。
- **`slogan`**：信息卡上的大字，是活动的一句话主张，不是活动名重复。
- **`signature`（落款）**：以邀请人视角写，口语化。默认「负责给你搭台的我」。

**当 `guest` 或 `event_date` 用了默认占位时，必须在交付前提醒用户**：嘉宾姓名 / 具体日期可以补齐后重新生成。

面向正式对象（外部嘉宾、领导、客户）时，提醒用户：这个 H5 带"拒绝按钮会逃跑"的恶作剧互动，风格偏轻松，正式场合可能不合适。

## 修改已生成的产物

改文案、换嘉宾、调日期——**改配置重新生成**，不要手工编辑产出的 HTML。产物是一次性生成物，配置才是可维护的源。

要调整视觉、布局、交互逻辑（这些不由配置控制）时，直接编辑 `assets/template.html`，改完后跑一次生成脚本验证锚点是否仍然命中。

## 模板说明

`assets/template.html` 是定稿产物，单文件，零外部依赖（花朵素材以内联 SVG data-URI 内联，字体用系统字体栈）。

关键实现细节和踩过的坑记录在 [references/template-notes.md](references/template-notes.md)，**修改模板前先读**，尤其是逃逸按钮那部分——它的定位切换、边界检测、最小位移约束都有非显而易见的处理。
