## 表结构

建议 10 个字段（对应 10 个水果槽位，共 10 行）：

| 字段名 | 类型 | 说明 |
|---|---|---|
| 素材用途 | text | 如"水果 lv0"、"游戏背景" |
| 层级序号 | text | 0–9，非水果素材留空 |
| 素材代号 | text | 如 PuTaoS |
| 要求尺寸(px) | text | 如 `80x80`，**必须与实际像素一致** |
| 文件格式 | select | PNG / JPG |
| 色彩模式 | select | RGBA / RGB |
| 需要透明背景 | select | 是 / 否 |
| 替换要求 | text | 如"同名覆盖，不可改名" |
| 参考文件大小 | text | |
| 最终贴图 | attachment | 回写处理好的成品 |

非水果素材（背景、按钮、序列帧等）可按需追加行，尺寸见 `daxigua_asset_map.md`。

## 数据来源

尺寸和色彩模式**必须用 Pillow 逐个实际读取**，不要按经验估算：

```python
from PIL import Image
im = Image.open(path)
print(im.size, im.mode)
```

## 已验证的坑

1. **附件上传只接受相对路径**
   传绝对路径会报 `unsafe file path`。必须先 `cd` 到文件所在目录，再用 `./filename` 引用。

2. **新建 Base 有索引延迟**
   刚创建的 Base 用标题搜索/解析会失败，或误匹配到其它同关键词的表。**可靠做法是从创建命令的返回里直接取 base_token**，不要事后再搜。

3. **附件需串行上传**
   并发上传易触发写冲突。串行执行；若中途超时，先回读检查已上传了几行，再补齐剩余的，不要整体重来。

4. **写入后必须回读校验**
   逐行核对附件文件名与「要求尺寸(px)」字段是否一一对应，并确认非水果行没有被误写。

5. **select 字段写值要用数组包裹**
   即使是单选也写成 `["是"]`。
